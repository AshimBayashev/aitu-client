# Aitu здорового человека

Неофициальный клиент [Aitu](https://aitu.io) для Windows. Веб-версия долго отправляет сообщения, не даёт разложить чаты по папкам, персонализировать вид чатов, присутствует много багов и неудобств. Этот клиент оставляет обычную переписку и даёт настроить вид под себя.

ВАЖНО! Проект не связан с BTS Digital. Вход идёт в ваш собственный аккаунт через окно Passport.

Установить для Windows можно из Microsoft Store: [Aitu здорового человека](https://apps.microsoft.com/detail/9ND7DC3NGZ6F?hl=ru-ru&gl=KZ).

## Функционал

- Список чатов, история и отправка текста
- Файлы, ссылки в сообщениях и фото профилей
- Эмодзи и голосовые: запись из поля ввода и прослушивание прямо в чате
- Ответы на сообщения и карточка чата справа
- Закреплённые чаты без ограничения по количеству
- Сообщения одного человека собираются в пачку
- Галочки доставки и прочтения
- Папки в духе Telegram: «Все», «Личные», «Группы», «Каналы» и свои
- Светлая и тёмная тема, свой цвет акцента, шрифт, размер, плотность списка и фон чата
- Уведомления о новых сообщениях
- Закрытие окна прячет клиент в трей, полный выход — из меню трея

Папки, закрепления и оформление остаются на этом компьютере. Переписка подтягивается из аккаунта Aitu.

## Запуск

Нужны Windows 10 или 11, WebView2, Node.js 20 и Rust со сборкой MSVC (Visual Studio Build Tools).

```bash
npm install --legacy-peer-deps
npm run tauri dev
```

Установщик:

```bash
npm run tauri build
```

## Как устроено

Окно собрано из трёх колонок: рельс папок, список чатов и открытая переписка. Поверх них выезжают настройки слева и карточка чата справа. Правая карточка сжимает переписку, а не ложится на сообщения.

Весь экран живёт в одном React-контексте, `src/state.tsx`. Сеть до него не доходит. Страница вызывает команды Rust через `invoke` и получает уже разобранные чаты и сообщения. Rust держит сессию и сам ходит в Aitu.

Сессия — cookie после входа через Passport. Страница приложения на своём origin в `api.aitu.io` с этой cookie не попадает, поэтому запросы делает процесс Tauri. Окно входа в capabilities не входит: у команд доступно только главное окно, и страница Passport их вызвать не может.

### Вход

Команда входа запрашивает адрес OAuth у `AuthService/GetPassportOAuthUrl` и открывает отдельное окно. Когда загрузка заканчивается на `aitu.io`, Rust забирает cookie для API и проверяет её вызовом `UserService/GetMe`. После успешной проверки сессия сохраняется, а интерфейс получает событие `aitu-session` и переходит в рабочий режим. Выход стирает сессию и возвращает экран входа.

Пока сессии нет, список чатов пуст. Демо-данные в репозитории нужны только для вёрстки в браузере, без Tauri они в аккаунт не ходят.

### Список чатов

Список приходит методом диалогов и обновляется примерно раз в 12 секунд. Тип собеседника на проводе — пользователь, бот, приложение, бизнес-чат, группа, обсуждение или канал. В списке это три вида: личный диалог, группа и канал. Бот, приложение и бизнес-чат выглядят как личные.

У строки есть название, аватар, превью последнего сообщения, время и счётчик непрочитанных. Поиск фильтрует уже загруженный список на этом компьютере и отдельный запрос на сервер не шлёт.

Аватарки берутся с публичного `media-cdn.aitu.io` по идентификатору файла. Для маленького аватара в идентификаторе бывает вопрос: кодируется только путь, исходный query остаётся как есть.

### Папки

Слева фиксированный набор: «Все», «Личные», «Группы», «Каналы». Личные, группы и каналы собираются из вида чата при каждом обновлении списка. Свои папки хранят явный набор идентификаторов. Чат, которого больше нет на сервере, из такой папки выпадает. Значок папки общий, подпись — её имя. Свои папки создаются и правятся на этом компьютере.

### Закрепление

Правый щелчок по строке чата закрепляет её или снимает закрепление. Числа закрепов нет. Новый закреп встаёт первым. Внутри закреплённых порядок берётся из этого списка, остальные чаты сортируются по времени последнего сообщения. Отдельной шапки «закреплённые» нет: у строки на превью стоит булавка. Выход из аккаунта закрепления не трогает.

### Переписка

История открытого чата запрашивается сразу и дальше примерно раз в 5 секунд. Лента прижата к низу: при смене чата и при новых сообщениях, пока пользователь сам не ушёл вверх. Прокрутка вверх отлипает от края, следующее своё или чужое сообщение вниз само не утягивает.

Сообщения одного автора, идущие подряд и не дальше пяти минут, рисуются пачкой: имя только у первого, между ними маленький зазор и смягчённый общий угол. Пауза длиннее пяти минут или другой автор начинают новую пачку.

В тексте узнаются адреса `http`, `https`, `www` и голые домены. Клик открывает только `http` и `https`. На рабочем столе ссылка уходит в системный браузер, в обычном браузере открывается в новой вкладке.

Вложения в истории показываются карточками. Файл сначала скачивается в кэш приложения и открывается программой по умолчанию. Фото профиля и часть медиа доступны с CDN без cookie. Загрузка своего файла идёт multipart-запросом на `media-upload.api.aitu.io` уже с сессией.

### Отправка

Пустое поле показывает круглую кнопку микрофона. Как только есть текст, файлы или идёт запись, на её месте кнопка отправки. Enter отправляет, Shift+Enter переносит строку.

Своё сообщение сразу появляется в ленте со статусом «отправляется». Когда история возвращает его с сервера, локальная копия сходится с серверной по тексту и времени. Если отправка не удалась, сообщение остаётся в ленте с пометкой, что оно не ушло.

Ответ ставится из контекстного меню сообщения, которое уже дошло или прочитано. Над полем появляется цитата. Уходит это отдельной командой ответа: идентификатор исходного сообщения и новое тело. В истории цитата берётся из исходных сообщений, которые сервер прикладывает к ленте.

Смайлики выбираются в панели у поля. Недавние запоминаются локально.

### Голосовые

Запись идёт с микрофона, пока пользователь держит сессию записи, не дольше трёх минут. Звук перекодируется в моно WAV 22050 Гц и отправляется как аудиофайл `voice.wav`. В истории Aitu возвращает его обычным файлом с тем же именем. Клиент узнаёт такие имена и показывает плеер в ленте: кнопка, ползунок и длительность. Файл с другим именем открывается снаружи, как документ.

### Галочки и прочтение

У исходящего сообщения четыре состояния. Пока оно уходит, крутится индикатор. После подтверждения сервером одна приглушённая галочка означает доставку, две акцентные — что сообщение прочитано. Ошибка отправки показывает, что сообщение не ушло.

Статус приходит внутри тела сообщения: доставлено или прочитано. Открытый чат помечается прочитанным по самому новому сообщению, и только когда окно развёрнуто и стоит на переднем плане. Свёрнутое или спрятанное окно прочитанным чат не отмечает, счётчик на сервере остаётся, и по нему можно показать уведомление. Когда окно снова оказывается перед глазами, открытый чат дочитывается.

### Карточка чата

Клик по шапке переписки открывает правую панель: аватар, имя, вид чата и медиа, которые уже есть в загруженной истории. Голосовые `voice.wav` в этом списке считаются аудио и играют внутри клиента. Повторный клик по шапке, крестик или Escape панель закрывают. При смене чата она остаётся открытой и показывает уже новый чат.

### Оформление

Настройки выезжают слева. Там тема, акцентный цвет, шрифт, размер, плотность списка и фон переписки. Значения сразу пишутся в CSS-переменные на корне страницы. Вместе с папками, закреплениями, недавними смайликами и локальным кэшем переписки они лежат в `localStorage` под ключом `aitu-client-v1`. Аккаунт Aitu этого состояния не знает. Сброс оформления возвращает значения по умолчанию и не выходит из аккаунта.

### Уведомления и трей

Новые сообщения для тостов считает отдельный поток Rust: он раз в 12 секунд перечитывает список диалогов и сравнивает счётчики непрочитанных с прошлым снимком. Первый снимок после запуска только запоминается, уведомлений по нему нет. Дальше тост уходит, когда счётчик чата вырос. Для чата, открытого в развёрнутом окне на переднем плане, тост не показывается: эта переписка и так на экране. Текст тоста — превью, обрезанное до 140 символов, или «Новое сообщение», если превью пустое.

Клик по уведомлению поднимает окно и открывает этот чат.

Крестик окна процесс не завершает: окно прячется, клиент остаётся в трее. Левый щелчок и двойной щелчок по значку, как и пункт «Открыть», возвращают окно. «Выход» завершает процесс. Значок может оказаться в переполнении трея, это поведение Windows.

Поток Rust нужен потому, что у скрытого WebView таймеры страницы останавливаются. Пока окно спрятано, список для уведомлений всё равно обновляется.

### Что откуда берётся

Профиль и адрес входа — Twirp JSON на `https://api.aitu.io/twirp/...`.

Диалоги, история, отправка, ответ и отметка прочитанного — grpc-web-text на том же хосте, без `/twirp`. Кадр — байт флага, длина protobuf в big-endian и сами байты. В `proto.rs` разобраны только поля, которые нужны экрану: идентификаторы, текст, автор, вложения, ответ и статус.

Скачивание медиа идёт с `media-cdn.aitu.io`. Своя загрузка — на `media-upload.api.aitu.io`.

### Сборка

`npm run tauri build` на Windows даёт установщик NSIS. Текст мастера установки русский. Тот же бинарник можно упаковать в MSIX и отдать в Microsoft Store. Имя пакета в магазине задаёт Partner Center. Идентификатор приложения в Tauri остаётся `local.aitu.client`, и сессия между такими сборками не сбрасывается.

Сборка macOS идёт на раннере GitHub Actions и даёт universal `.dmg`. Подписи Apple у неё нет: при первом запуске файл открывается через контекстное меню.
